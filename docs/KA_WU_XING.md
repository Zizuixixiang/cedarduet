# 襄阳卡五星（三人）

玩法由 CedarDuet 实现，需求见 [Issue #2](https://github.com/Zizuixixiang/cedarduet/issues/2)。游戏 ID 为 `ka_wu_xing`，三人84张实体牌：筒、条各1–9和中发白各四张；无万、风、花。没有必须缺门条件。国标 `mahjong` 仍独立使用四人和8番规则。

## 创建时选择房规

普通新建、三人邀请和 NPC 补位共用 `game_options`。选项仅创建时确定，进入房间后不能变更。网页建房与房内规则展示同一份已保存选项；MCP 按需读取本 Guide 或房间完整状态。未提供选项的房间全部使用下表默认值，旧单手房不会自动启用新房规。

| 字段 | 合法值（严格类型） | 默认 | 结算含义 |
| --- | --- | --- | --- |
| `double_hu` | `true` / `false` | `false` | 同一普通弃牌可两人胡，各自独立计分；抢补杠保持单响 |
| `gang_discard_double` | `true` / `false` | `false` | 杠补后立即弃牌被胡，赢家另得杠上炮×2；不叠抢杠胡 |
| `liang_liability` | `true` / `false` | `false` | **赢家已亮倒**时，接炮或抢杠由来源承担两份胡分及两份漂分 |
| `consecutive_kong_double` | `true` / `false` | `false` | 同一玩家未弃牌前连续完成的第1/2/3…杠，该次杠分乘1/2/4…，不追溯前杠 |
| `horse_count` | 整数 `0` / `1` | `0` | 1为自摸后从剩余墙尾翻一马；无余牌不翻、不收费 |
| `piao` | 整数 `0` / `1` / `3` / `5` | `0` | 每次胡牌、每个付款份额另付固定漂分 |
| `joker` | `"none"` / `"red"` | `"none"` | 红中普通字牌 / 手牌红中万能 |

仅打一手，打完结束。旧 API 可传整数 `rounds=1`，该字段不再保存；`rounds=4/8` 及其他值明确拒绝。

拒绝未知字段、非法枚举、数字冒充布尔、布尔冒充整数及其他游戏的专属选项。不支持多马；不能在出牌或加入房间时覆盖房规。

## 基础牌型、亮倒与响应

庄14张先打，闲家13张；任意对子作将，四面子一对或七对，实体四张可作两对。不能吃；可碰、直杠、补杠、暗杠。摸牌墙头、杠补墙尾。

平胡×1、碰碰胡×2、清一色×4、七对×4、龙七对×8、双龙及以上七对×16。七对族择一，不叠碰碰胡或四归一。非七对的非杠四张：含明碰为明四归一×2，否则暗四归一×4，多组只取最高一项。大三元×8与小三元×4互斥；手抓一（四副露剩单张成对）×4。实际胡入5筒/5条，且存在以手中自然4、6组成456的合法拆分，计卡五星×2；已有456胡别张不计。

杠上开花、抢杠胡、海底自摸各×2。已开启的杠上炮×2参与牌型倍数计算。不同项相乘，普通牌型封顶×8，双龙及以上七对封顶×16；封顶后仅赢家亮倒再×2（最高×32）。马分、漂分、杠分不参与该封顶。自摸平胡可胡；点炮最终至少×2；抢杠×2可胡。

在本人出牌时选择“亮倒并打…”：弃牌后必须听牌，公开固定听口和固定余手牌。此后只能胡或打刚摸牌，禁止碰及所有杠。新摸暗牌仍仅本人可见。每位亮倒者在荒庄时向每位未亮倒者付1基础分，全亮/全未亮均不赔，不另查叫。亮倒包赔与这一荒庄赔付分别处理。

胡优先于碰杠，同级按距来源的座次响应。默认单响，第一位选择胡后结束；开启双响时，收齐同一普通弃牌的合法胡响应，再分别结算。任意一人胡后不能再碰杠；另一人可胡或过，不能互付赢家分。已有确认胡时须完成剩余胡/过响应才能认输或离开，不能通过退出抹掉已确认的胡分；断线后仍可恢复响应。弃牌仍只有一张实体牌，两份胡牌记录引用同一来源。过合法胡（含自摸不胡）后，至本人下次摸牌前不能接炮或抢杠。最后一张弃牌仅可胡。补杠先检查抢杠，未完成的补杠不收杠分；暗杠不可抢。

## 独立账目与钱包

- 胡分：自摸另两家各付最终倍数；普通接炮/抢杠仅来源付一份。开启亮倒包赔且赢家亮倒时，来源改付两份；双响逐赢家独立计算，另一赢家不会因此付款。
- 漂分：每份胡分同时另付固定 `piao`。例如 `piao=3`，自摸每家在胡分之外另付3；普通接炮来源另付3；亮倒包赔来源另付6。荒庄、认输和杠本身不收漂。
- 马分：`horse_count=1` 时任意自摸胡牌后仅翻墙尾一张，筒条按点数1–9，中发白均为10，两家各额外付该值。没有余牌就无马分。马牌从墙中移入公开马牌区，不再参与摸牌；未翻的牌墙不公开。接炮、双响、抢杠、荒庄均不买马。
- 杠分：直杠来源付2，补杠另两家各付1，暗杠另两家各付2。连续杠选项只改变本次完成杠的金额；抢补杠不收未完成杠，荒庄保留已记杠分。

各项先按基础分分别记账，再合成该局 `score_units`；认输者赔另两家各1并保留当前杠分。`stake=0` 仅记分不移动钱包。非0底注在单手结束时一次用本局净分乘底注：真实输家最多扣当前可用钱包，实际可付总额按赢家应得比例分配，整数余数按座次；不透支。`requested_settlement_deltas` 是余额裁剪前金额，`settlement_deltas` 是实际钱包变化。NPC 只记逻辑分。仅站内娱乐积分，无真实钱。

## 红中万能的明确边界

`joker="none"` 完全保留红中字牌语义。`joker="red"` 不增加任何实体牌：四张红中仍计入84张，每张有独立 ID。**仅本人持有的红中可作万能**，允许作将、刻子、顺子或七对中的缺牌；也可作自然红中用于对/刻。不能通过替代制造超过实体牌限制的持有手牌。

红中可以弃出；他人接炮时该张只能按自然红中参与胡牌，不能把外来红中当万能。红中不能碰或杠，其他牌的碰杠仍要求相同自然实体牌，不能以红中补足。普通胡与七对均支持万能拆分。胡牌手牌或副露含实体红中时，七对只计普通七对，不借万能凑龙七对/双龙七对；无论是否七对，所有四归一均不计。整副牌不含红中才按普通规则计四归一。清一色要求存在有效同色替代拆分；三元只计自然字牌组成，不把替代发白算成三元。实际胡入5与自然4、6组成的嵌张才计卡五星，红中替代4/5/6不能冒充该番型。

亮倒听口按当前红中模式的自摸集合计算；听红中可能仅允许自摸，外来红中必须按自然字牌重新验胡，不能把全部听口理解为都可接炮。亮倒后固定手牌和听口不能更换，新摸红中可胡或原样打出。服务器产生完整合法动作，网页、MCP 与本地 NPC 使用同一判定，不接受客户端自报万能分配、番数或听口。

## 单手结束与恢复

胡牌（双响收齐胡/过响应）或荒庄后直接结束并结算，没有第二局动作。认输赔另两家各1并保留杠分。刷新、断线或服务重启恢复当前手牌与合法动作，不重新发牌，重复终局请求不重复扣筹码。

双响已确认胡但尚未完成响应时，超时归档保留已记杠分与已确认胡分；未确认的响应按过处理，不另收荒庄或认输分。其余单手归档保持原行为。

旧单手存档照常加载；历史已结束多局的结果、累计分及逐局回顾只读保留，不迁移或改写存档，不恢复续局入口。

## MCP（按需 `get_guide(game="duel:ka_wu_xing")`）

调用外壳：`play(game="duel", action="...", params={...})`。身份来自路径 Token 或 Bearer 鉴权，不能代报别人的 `player_id`。专属选项只放 `params.game_options`，不扩充公共 `play` schema。

普通人机桌调用 `new`：

```json
{"game_type":"ka_wu_xing","target_player_count":3,"fill_with_npcs":true,"stake":0,"game_options":{"double_hu":true,"gang_discard_double":true,"liang_liability":true,"consecutive_kong_double":true,"horse_count":1,"piao":3,"joker":"red"}}
```

本人小机加两名 NPC 在上述参数加 `"include_human":false`，无需模型供应商。三位不同账号/家庭的小机，由房主 `invite`，参数同上但省略补位；另两位分别鉴权调用 `join`，`params={"invite_code":"返回的邀请码"}`；房主 `start`，`params={"room_id":"返回房间号"}`。

`state` 使用 `params={"room_id":"...","wait":false}`，丢失上下文时加 `"full_state":true`。MCP v2 首次或旧协议迁移时返回 `bootstrap:true` 和 `room`（规则、牌桌、本人 `private_state`）；普通响应只给 `r`、未消费的 `events`、变化的 `private`，不能行动时带 `wait`。下一次 `move` 的 `revision` 使用响应 `r`。请求例：`params={"room_id":"...","revision":当前r,"move":{"action":"act","action_id":"服务端动作ID"}}`。

按顺序应用所有事件，包括自己的动作；`private.+/-` 按实体 ID 增删本人手牌，其余私有键替换，缺省不变、null 清空。合法动作以 bootstrap 的 `private_state.legal_actions` 为基线，后续 `private.legal_actions` 替换（空数组清空）；只复制当前动作的 `action` / `action_id`，不提交 label、kind、番数或手牌。亮倒 ID 为 `liang:<实体牌ID>`，网页先选牌再确认“亮倒并打…”。

`events=[actor,action,delta]` 的 `revealed_added` 合并本次亮倒者，`kong_added` 追加本次杠账；不会重发之前的亮倒手牌或杠账。单手普通事件不发送 `round_state`。亮倒首次公开固定手牌、局末/终局公开结果及手牌属于必要信息。显式 `full_state` 返回独立可恢复的 `snapshot`（含规则、当前本人手牌/动作、完整局末回顾），原子跳过已覆盖动作，未读文字仍在下一次普通响应交付一次。未知上下文先 bootstrap；同账号重连沿用持久游标，不自动重发历史，丢包/丢上下文用 full_state，勿重放已成功 move。

量化与复现见 [MCP token 验收](KA_WU_XING_MCP_TOKENS.md)。大厅标签按普通一次 state + move 的压缩 JSON 正文估算；bootstrap、full_state 与终局另计，根工具包装另计，范围不是计费上限。

`revealed` 是亮倒固定手牌和听口，`kong_scores` / `kong_ledger` 是完成杠账目。终局分别展示胡、马、漂、杠及本局净分；`multiplier` 为倍数，不是国标番数。公共投影不含未公开手牌或牌墙；每位 AI 仅获得本人私有状态和当前可用动作。

## 来源与本版取舍

地区、平台之间存在差异，本版是明确的可选房规组合，不声称唯一襄阳规则。

- [Newton 襄阳卡五星](https://www.newton.com.tw/wiki/%E8%A5%84%E9%99%BD%E5%8D%A1%E4%BA%94%E6%98%9F)：参考三人84张、双响、亮倒赔付及荒庄庄家例外；新选项默认关闭以兼容已有房间。
- [棋牌乐卡五星](https://qipai.love/kawuxing/)：其单响、仅亮倒自摸买马与本版有区别。本版按本次需求允许双响开关，并在开启买马时让所有自摸翻一马；不复制其限制。
- [每日头条玩法资料](https://kknews.cc/zh-cn/game/5orgqxl.html)：参考筒条点数与中发白10的计马方式。本版只提供一马，固定漂0/1/3/5，避免不明确的多马或各人动态叫漂流程。该资料孝感段的“他人接杠翻倍”与本版不同，本版不采用跨玩家接杠翻倍，只计算同一玩家未弃牌前连续完成的杠。
- [BluffKing 平台页](https://bluffking.ai/en/product/kwx/) 提供买马、漂、红中万能和连续杠等平台可选项；其 classic 默认开启连续杠，本版为了旧房兼容默认关闭。其亮倒描述让输赢双方亮倒均加倍，本版延续仅赢家亮倒加倍。页面未明确红中全部细则，本版红中语义以上述约束为准。
- [zocet](https://kawuxingmajiang.zocet.com/) 与 [百度癞子条目](https://wapbaike.baidu.com/item/%E7%99%9E%E5%AD%90/58983176) 在本次核验中未能访问，未用作已验证规则证据。
