# 吹牛骰子按需 Guide

同一 `liars_dice` 入口，默认原版·淘汰赛（5骰，1不万能，输者少1骰，0骰淘汰）。旧请求不传房规继续原版。
平台 MCP：`play(game="duel",action=...,params={...})`；身份由鉴权决定，不接受代选别人。
详细 Guide 用 `get_guide(game="duel:liars_dice")`，不会重复注入其他游戏。

## 创建和选座

`new` / `invite` 的 `params.move` 是房规，Web 原开房/邀请面板用 `game_options`：

```json
{"mode":"party","literal_dice":false,"team_mode":"none"}
```

普通2人房可人类+绑定小机直接玩，不必邀请。酒桌可自选 `stake>=0`：0为娱乐局，非0只在整桌结束时结算平台筹码。本局分数从0起，允许负数，不涉及真钱。房规开局后不可更改，重赛继承。

组队可选 `team_mode:"teams"`，仅4/6人，红蓝2+2或3+3，每人独立一盅5骰，只看本人骰面，全桌骰子全部计数。固定座序逐人行动，同队可连座、叫点及互相质疑，败者先叫；队伍不改变行动权。4/6人普通6/9起，斋/叫1为4/6起，上限28/42，有骰计骰20/30。仅共享队分，败者队伍基础扣一次1分，即使同队互相质疑也不重复扣分。
`random_teams:true`（默认）直接原流程随机分组。`false` 才进入开局前选座：

```json
{"action":"move","params":{"room_id":"ABCDEFGH","revision":2,"move":{"action":"choose_team_seat","team":"blue","seat":3}}}
```

红蓝座位从1起；点新空位自动释放旧位，仅本人可操作。人类在原网页点+，小机仅鉴权MCP自选，无人类代操作入口。开房20秒后房主 `start`，不要求人人选座；未选人/机随机入余位。NPC不提前入座，原 `start(fill_with_npcs:true)` 才随机补位。邀请房沿用至少一名外部受邀者加入的条件。开局后选座关闭。新酒桌普通房（含手动组队）仅在真正开局时随机排座一次，之后固定，不按每轮重洗；红蓝可相邻，手动队伍归属与队内席位顺序保留。筹码待确认/选队阶段不洗座。邀请房沿用原有开局shuffle，不额外重洗；普通classic及其他游戏不变。旧 `pairs` 创建参数兼容为两队；旧已开局队伍不重排。不实现接力淘汰。

## 基本叫点、围骰和斋

`move={action:bid,quantity:3,face:2}`；叫斋加 `exact:true`；叫1自动斋。普通2–6时1百搭；斋不百搭。加叫须数量增加或同数点数增加；切斋也须加叫。斋后整轮锁斋；不实现飞斋、降数转斋。

普通首叫默认 `ceil(1.5×盅数)`；5人8起是向上取整的线上约定，可设 `opening_five:7` 改7起；其他人数不变。斋/叫1至少盅数。

新酒桌默认：围骰为5骰可借1凑所叫实点，计6（+1）；全围为5骰同一实点且叫此点，计7（+2，不再叠加+1）。全1叫2–6仅百搭计5，叫1计7。斋不借1凑围骰，但同实点全围仍+2。叫数公开上限为每盅7，避免以实际牌型上限泄密。
首叫前，仅当前行动者的己盅5点各异（不要求连续）可以 `move={action:reroll}`，每人每轮一次（旧共盅房仍队友共享次数）；只刷新己方私骰，不公开骰面，行动权不变。已有叫点后不得重摇。

## 可选房规

全部在创建时选择；抢开默认开启，其余下列开关默认关闭。基础围骰计数和限次重摇仍默认启用，组队默认不启用。

| 开关 | 固定线上约定 |
|---|---|
| `rush_open:true` 抢开（新酒桌默认开启） | 每次合法叫点后10秒，所有其他在场人类、绑定小机、NPC可 `move={action:rush_open}`，包括同队，不能抢自己（旧共盅桌保留不能抢己盅）。窗口内暂缓下一手加叫与投降；最先通过事务验证的有效操作结算一次，无抢开额外加倍。到期仍由原下家正常叫点/质疑。可设false关闭；旧房缺少字段按关闭保留。 |
| `literal_dice:true` 有骰计骰 | 围骰不+1、全围不+2、单骰不重摇。**普通1仍百搭，斋不百搭**。叫数上限每盅5，起叫门槛不变。 |
| `cup_penalty:true` | 被开骰的叫点者持围骰/全围且最终败，罚×2；牌型不必与叫点一致。有骰计骰不关闭此独立处罚。 |
| `extreme_penalty:true` | 实际严格不到叫数一半且叫点者败，或严格超过叫数两倍且质疑者败，罚×2；等于边界不触发。 |
| `allow_surrender:true` | 已有叫点时当前行动者可 `move={action:surrender}`，固定认罚基础一半0.5分；不叠加开骰处罚/反转/陪扣。默认揭盅，确认后全员重摇。可同时选 `surrender_no_reroll:true`，不揭骰、保留各盅进入下一轮。房间 `resign/leave` 是结束整桌，不是本轮投降。 |
| `dark_rule:true` 天黑黑 | 全场没有所叫点数的真实骰面，反转通常开骰胜负；1百搭不算所叫实点。先反转，再依最终败方判断独立加倍。 |
| `companion_penalty:true` 陪扣 | 额外虚拟d6，按固定参与者顺序1起映射人/机/NPC；超人数重掷（异常随机源64次失败则整次事务撤销）。抽到其他个人/队按主败方原始倍率陪扣；抽到本人/同队，本受罚单位再×2。不递归抽取陪扣者，不涉及实际饮酒。 |
| `team_mode:"teams"` | 上述红蓝两队，仅共分，每人独立5骰，4/6人；随机/手动选座沿用同一开房流程。 |

## 权威结算与结束

`move={action:challenge}`：计数达到叫数，通常质疑者败，否则叫点者败。新桌每人/队初始0分；最终胜方+1，败方按现有倍率扣1/2/4分。加倍相乘后**每受罚个人/队每轮至多4倍、4分**，陪扣也封顶4。抽中败者本人/同队时自身处罚再×2并封顶；抽中胜者本人/同队时奖励与陪扣累加。红蓝组队只共享积分，2/3人不叠加得失分；同队无特殊豁免，+1与-1/-2/-4净结算为0/-1/-3。
权威 `round_result.penalties` 每项含 `hits/raw_multiplier/multiplier/cap/capped/base_half_units/deduction_half_units/score_delta/score_after`；`companion` 记录虚拟骰与映射座位，`dark_reversed` 记录反转，`cup_bonuses` 记录各盅加数。内部 `score_half_units` 使用整数半分单位运算；对外以0.5分精确显示，胜负记录只辅助。

结算后仍各5骰，不淘汰。败方成为当前行动者，提交 `move={action:acknowledge_round}` 开始下一轮并先叫。正常全盅重摇；投降不重摇保留骰面。抢开截止由服务器时间决定，延迟到达的请求按服务器接收后的事务校验时间判定，不接受客户端时间回填。截止会递增一次revision；重连刷新获取最新值。所有酒桌行动须带最新 `revision`，旧版本/重复结算拒绝。任一真实在场参与者可 `move={action:end_session}` 结束整桌，保留积分和记录，未结算轮次不计分；按本局累计积分从高到低排名（红蓝组队只按队分排名），同分并列第一，零个已结算回合则无胜负。结束弹窗展示完整排名和已完成轮数，NPC/超时接管不可结束整桌。

0 筹码只记录局内积分；非0筹码在整桌结束时结算一次。每名真实败者最多付一份 stake，真实第一名（组队按最高队分）平分实际败者池，整数余数按稳定座位顺序分配；NPC不收付筹码。零个已结算回合、全员并列、仅NPC获胜或无真实输家时筹码退回，不发成就奖励。

旧开发稿已开局酒桌房没有 `party_rules_version:2` 时保持无围骰加数/无单骰重摇；修正有骰计骰的1百搭含义。原版存档不变。

新开局组队桌存储 `team_rules_version:2`，与 `party_rules_version` 独立。无标记/版本1的旧已开局桌继续原共盅、队间轮换、起叫上限及积分规则，不迁移、不补骰、不重置积分；旧等待房正式开局及重赛新桌才使用版本2。公开投影/MCP携带该版本以区分标签，绝不通过缺失骰盅推测或升级存档。手动队伍名单与固定行动座序独立，随机座序不能改队伍；未来抢开资格也不得按队伍排除同队玩家。

积分版本独立保存为 `scoring_rules_version:2`（包括等待房）；无标记/版本1旧房保持输扣赢0，开始、重启、重连、归档均不升级。重赛是新桌，使用新口径。已结束记录不重算。
每轮 `penalties` 保留原始处罚及倍率，`rewards` 记录开骰胜方+1，`score_changes` 按计分单位给出唯一净变动与结算后分数；顶层 `score_delta/score_after` 对应败方单位净变动与最终分数。投降只扣败方0.5，不产生奖励。所有得失分与回合记录在同一事务保存，继续以整数半分累计。

## MCP 增量协议

原版MCP协议保持兼容。酒桌首次返回 `bootstrap:true` 与必要安全上下文，`r` 为权威revision；下一次动作传 `revision:r`。
之后 `state/move/wait` 只返回变化：`events` 按序为 `[玩家ID,move]` 或 `{round_result:本轮权威结算}`，不重复全盘/历史/巨大legal_actions；自己动作也应用一次。
`delta` 字段替换（缺省不变、null清空）；`delta.seats=[[队,1起座号,成员或null]]` 只更新座位变化。首份手动面板在 `room.selection`，Web仍为 `room.team_selection`。
`private` 仅本人骰变化和重摇资格（旧共盅房仍己队骰）；别人的新骰永不可见。`delta.scores/team_scores` 更新积分；`delta.round/phase/next` 更新轮次；`acknowledge_round` 清空当前叫法，`bid` 更新叫法，`challenge/surrender` 的权威结果清空叫法。无变化只返回 `r`，非本人回合另有 `wait`。
`state(full_state:true)` 显式获得完整安全快照（含房规/历史），原子重置本人增量基线，快照覆盖的动作不重复；尚未读聊天本次交付。所有中间叫点、揭盅事件按序交付，不因跨过多个回合而丢失。


抢开协议：`rush_until` 是服务器 Unix 秒截止时间，`server_time` 是返回时的服务器秒；窗口内 `actions:[{action:"rush_open"}]` 表示本人可抢，空列表表示不可抢。不是通常行动权转移，`next` 仍是截止后的下家。第一次变化主动唤醒MCP wait；已看到机会但不抢，可以继续 `state(wait:true)` 等结算/截止，避免忙轮询。截止 `delta.rush_until:null` 清空机会，普通叫点仍只允许next。full_state和网页返回本人 `private_state.can_rush`，不公开别人私骰。

系统NPC的抢开采用本地有界策略，只读己方骰盅及公开叫点，独立随机延迟1.5–8秒响应，不等待外部模型；普通回合仍走原NPC决策链。后台截止任务、重连读取及MCP wait截止唤醒均可恢复回合；重启读取已持久化的截止时间。纯NPC酒桌可推进，但保留原有无人参与自动行动预算，不无限自动跑局；真人/绑定小机行动后按原规则恢复预算。
